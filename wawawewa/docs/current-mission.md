# Current mission: Homepage — "Futuristic" redesign

Temporary scratch file — delete once the homepage-sections mission is fully done (see CLAUDE.md "Current mission tracking").

## Goal
Rework the homepage (and site-wide header) from the plain Black & Gold layout into the "Futuristic" direction — same palette, new interaction language — per `docs/store-build-plan.md` → "Design evolution".

## Decisions made
- Custom cursor (mockup's `cursor:none` + ring/dot follower): **skipped**, kept the native cursor (UX/accessibility tradeoff).
- Site-wide header restyle: **yes** — gradient wordmark, translucent sticky background, JetBrains Mono drawer label all apply everywhere, not just the homepage.
- Moving/interactive effects (hero parallax, magnetic buttons, button tap-scale): desktop/tablet only — explicitly disabled below the `mobile` breakpoint (480px) per user request, even though most would have no-op'd anyway on touch.
- Sections are being built one at a time, desktop + mobile together per section, in the design's top-to-bottom order: Hero → Marquee → Best sellers → Categories/Lookbook → Testimonials → About → FAQ.

## Design specs pulled from Claude Design (2026-07-28 fetch)

Full desktop (`Homepage Futuristic.dc.html`) + mobile (`Homepage Futuristic Mobile.dc.html`) mockups were re-fetched via `DesignSync` (project `6e15106a-a49d-45e9-85cb-b7e220f17f7e`, `PROJECT_TYPE_PROJECT`, not a design-system project — `list_projects` won't show it, use `get_project`/`list_files`/`get_file` directly with the project ID). Recording specs here so future sections don't need a re-fetch. All measurements below: desktop / mobile.

**Best sellers** (`◆ BEST_SELLERS.LOG` eyebrow + "המוצרים המובילים" heading, mono/Heebo per existing pattern):
- Grid: `repeat(4,1fr)` gap 22px / `repeat(2,1fr)` gap 14px.
- Card: `1.5px solid #c9a24b` border, radius 18px/14px, image height 190px/130px (object-fit cover via `image-slot`), body padding `14px 16px 16px`/`10px 12px 12px`.
- Card body: product name (Assistant 700 14px/12px), row with price (Heebo 800 14px/12px, gold) + "הוסף" pill button (Assistant 700 12px/10px, `1.5px` gold border, pill radius, padding `6px 14px`/`4px 10px`).
- Desktop-only hover (`data-cursor-hover` + `tiltMove`/`tiltLeave` in the mockup JS): 3D tilt (`perspective(600px) rotateX/rotateY` from cursor position within card, ±7deg), border brightens to `#e0bd6e`, `box-shadow:0 20px 40px rgba(201,162,75,.18)`, inner image scales to 1.08. Mobile has no tilt — instead a plain `:active` press: `scale(.97)` + border to `#e0bd6e`.
- Product data (name/price/image) in the mockup is placeholder (`מוצר 01`…`08`, `₪ 00`) — real build reads actual WooCommerce products via the **manual ACF relationship field** decided below, not the mockup's dummy loop.
- **Decision**: product source is a **manual picker** — an ACF relationship field on the strip (editor hand-picks which products + order), not an automatic "best-selling" WooCommerce query. Reuse WooCommerce's own `$product->get_image()`, `get_price_html()`, and `woocommerce_template_loop_add_to_cart()` for the image/price/cart-button — do not hand-roll add-to-cart/AJAX, per CLAUDE.md "never duplicate WooCommerce."

**Categories/Lookbook** (`◆ INDEX.CATEGORIES` eyebrow + "קטגוריות" heading): desktop 3-col asymmetric grid `1.3fr 1fr 1fr` gap 20px, each image 340px tall, radius 18px, staggered reveal delays (0/.1s/.2s). Mobile: single column stack, gap 12px, image height 220px each, staggered reveal delays (0/.08s/.16s). Three fixed image slots (no repeater implied by the mockup, but likely worth an ACF repeater of image+link so editors can add/remove categories rather than hardcoding exactly 3).

**Testimonials**: no eyebrow/heading in the mockup (starts directly with the grid) — 3-col desktop `repeat(3,1fr)` gap 20px / mobile stacked column gap 14px. Card: `1.5px solid #c9a24b` border, radius 18px/14px, padding 24px/18px, `★★★★★` stars line (Heebo 700 14px/12px gold), quote text (Assistant 400 15px/1.6 / 14px/1.6), author (Assistant 700 13px/12px, muted `#b7ac97`). Data shape: `{ quote, author }` — maps to an ACF repeater.

**About/brand strip** (`◆ ABOUT_US` eyebrow): split layout, image left/right + copy — desktop `1fr 1fr` grid in a bordered/rounded (`24px`) container, image full-height; mobile stacked (image on top, 200px tall, then copy), rounded 18px. Copy: eyebrow (mono), heading (Heebo 800 27px/20px), body (Assistant 400 15px/14px, muted), link "קראו את הסיפור המלא ←" (Assistant 800 13px/12px, gold, no visible href in mockup — needs a real link field).

**FAQ accordion**: heading "שאלות נפוצות" only, no eyebrow. Single-open accordion (mockup state `openFaq`, only one row open at a time, "+"/"–" sign toggle). Row: `1.5px solid #c9a24b` border, radius 16px/14px, header row padding `18px 22px`/`14px 16px` (question text Assistant 700 15px/13px + sign Heebo 800 18px/16px gold), answer padding-bottom reveal `0 22px 20px`/`0 16px 16px` (Assistant 400 14px/13px, muted). Data shape `{ q, a }` — maps to an ACF repeater; needs real JS accordion module (`js/faq-accordion.js`), single-open behavior like the mockup.

**Newsletter/footer band**: already scaffolded in `footer.php` (Gravity Forms) per store-build-plan.md — mockup shows a simpler visual (heading "הצטרפו למועדון" + subcopy "10% הנחה..." + email input + "הרשמה" pill button) that our Gravity Forms-based footer should visually match but not architecturally replace. Footer bar below: `© wawawewa 2026` + תקנון/משלוחים/יצירת קשר links — already exists.

Both mockups also reference `image-slot.js` / `support.js` (design-tool runtime only — not ported into the theme; theme uses ACF image fields + real `<img>` output instead) and use a custom cursor (`cursor:none` + ring/dot) on desktop only, which — per the standing decision above — is skipped sitewide, including for these later sections; treat every `cursor:none`/`data-cursor-hover` in the mockup as "hover state still applies, native cursor stays."

- [x] *(unrelated to the homepage mission, logged per the mandatory rule above)* SVG uploads enabled in the media library — admins (`manage_options`) only, since raw SVG can carry a script/XSS payload and this isn't a content sanitizer, just a capability gate (`inc/setup-functions/svg-upload.php`). Also patches `wp_check_filetype_and_ext` (WP's mime sniffing doesn't recognize SVG by default) and reads the SVG's own width/height/viewBox into attachment metadata + admin CSS so the media grid thumbnail isn't a broken/oversized generic icon.
