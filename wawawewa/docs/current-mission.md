## Goal
Build the WooCommerce single product page per `Product Page Futuristic v2.dc.html` (project `6e15106a-a49d-45e9-85cb-b7e220f17f7e`), reusing real WooCommerce data/functionality everywhere possible rather than hand-rolling anything WooCommerce already provides.

## Decisions made
- **Variation UI**: style WooCommerce's own native variations form (handles price/stock/image swaps, AJAX add-to-cart automatically) rather than hand-building the mockup's custom color-circle/size-pill swatches with custom JS bridging to WC's variation system. Not pixel-identical, but zero custom sync logic to get wrong. User confirmed via AskUserQuestion.
- **Gallery**: the theme already declares `wc-product-gallery-zoom`/`-lightbox`/`-slider` support (`inc/woocommerce.php`) — WooCommerce's own default gallery template + JS (flexslider, zoom, photoswipe lightbox) already does everything the mockup's main-image-plus-4-thumbnails layout needs. Only restyling via SCSS, no template override, no custom gallery JS — a functional bonus over the mockup (real zoom/lightbox it doesn't show).
- **"◆ 360°" badge**: skipped — it implies an actual interactive 360° product viewer, which isn't being built. Showing the badge without the feature would be misleading.
- **Related products' shine-sweep + "quick view" hover overlay**: skipped — no quick-view modal is being built, and a shine effect with no purpose is pure decoration for decoration's sake. Reused the same tilt-hover treatment already established for the homepage Best-sellers cards instead, for a consistent interaction language.
- **Star rating**: unlike the homepage Testimonials strip (which hardcodes 5 stars because its mockup data has no real rating field), this is genuine WooCommerce review data — rendered as real filled/empty stars from `$product->get_average_rating()` rounded to the nearest whole number, with the real `get_review_count()`. Section is skipped entirely if there are no reviews yet.
- **Accordions** (Description / Shipping & Returns / Care): extracted the homepage FAQ strip's accordion styling out of the homepage-scoped `.strip-faq` into a new shared `sass/components/_accordion.scss` (generic `.accordion` BEM classes), since it's now used in two places — avoids duplicating the same CSS. `js/faq-accordion.js` needed no changes; it already targets generic `[data-faq-accordion]`/`[data-faq-toggle]` attributes, not FAQ-specific classes.
  - "תיאור מלא" (Full description): real `$product->get_description()`.
  - "משלוח והחזרות" (Shipping & returns): **global** ACF option field (`product_shipping_returns_text`, new "מוצר" tab on site settings) — same policy text across the whole catalog, not per-product.
  - "מידות וטיפוח" (Sizing & care): **per-product** ACF field on the `product` post type (`product_care_instructions`) — care instructions genuinely vary by product/material. Accordion row is skipped if empty.
- **Trust badges row** (free shipping / 30-day returns / secure payment): global ACF option fields (`product_trust_badge_1/_2/_3`, same "מוצר" tab) — same 3 lines under every product, not worth re-entering per product.
- **Related products**: reused WooCommerce's own related-products query (real "same category/tag" algorithm) via overriding `woocommerce/single-product/related.php` for card styling only — not a custom repeater. Updated `woocommerce_output_related_products_args` filter (`inc/woocommerce.php`) from 3 cols/3 posts to 4 cols/4 posts to match the design.
- **Breadcrumb**: reused WooCommerce's own `woocommerce_breadcrumb()` (already fires the correct hook/filter) restyled via CSS, instead of hand-rolling HOME/CATEGORY/PRODUCT text.

- [x] **Build tooling fix (unplanned, requested mid-mission)**: merged the separate `sass/woocommerce.scss` compile entry into `sass/style.scss` — WooCommerce styling (`sass/plugins/woocommerce/*`) now compiles through the same single stylesheet as everything else, so saving `style.scss` (or any partial it imports) refreshes all compiled CSS instead of needing to remember to also save the separate `woocommerce.scss` entry point. Deleted `sass/woocommerce.scss` and the stale compiled `woocommerce.css` at the theme root; moved its 3 color variables (`$woocommerce__color-error/-success/-info`) into `sass/abstracts/variables/_colors.scss`. Updated `inc/woocommerce.php`'s `wawawewa_woocommerce_scripts()` to stop enqueuing the now-deleted `woocommerce.css` — **found and fixed a real hook-order bug while doing this**: its inline `@font-face` (WooCommerce's own star icon-font, still needed for the *default* `.star-rating` markup on shop-loop/review/widget pages we haven't overridden — our custom `rating.php` override just doesn't need it for the single-product page specifically) was re-attached to the `'wawawewa-style'` handle, but `inc/woocommerce.php` is `require`d *before* `inc/setup-functions/enqueue.php` in `functions.php`, and both hook `wp_enqueue_scripts` at the same default priority — so without bumping this hook to priority 20, it would have tried to attach inline CSS to a handle that isn't registered yet and silently no-op'd (the exact same class of bug CLAUDE.md already documents for the header.php RTL-swap case). Updated `CLAUDE.md`'s Stack/Directory-structure/Conventions sections and `docs/store-build-plan.md` to stop referencing the now-deleted `woocommerce.scss`/`woocommerce.css`.
- [x] **Bug fix (unplanned, found on staging)**: a default WordPress sidebar (Recent Posts/Comments/Archives/Categories, plus a search box) was rendering at the very bottom of the product page. Root cause: WooCommerce's own `templates/single-product.php` fires `do_action( 'woocommerce_sidebar' )` right after the main content, before the footer — nothing in this theme's own code was hooked there, but something evidently was. Fixed with `remove_all_actions( 'woocommerce_sidebar' )` in `inc/woocommerce.php`, since this design has no sidebar concept anywhere (every homepage strip and the product page are full-width) — whatever renders there should never show, regardless of what it turns out to be.
